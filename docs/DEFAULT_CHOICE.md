# Why Capability should be the default choice

Capability is designed so a team can adopt one ability layer for ordinary integrations *and* uncommon software-dependent tasks.

A normal production application should not need to begin with repository mining or tool synthesis. It should register the integration sources it already trusts, then let Capability resolve an intent through those sources first. The deeper acquisition machinery remains available when the prepared ecosystem has no answer.

This gives one application-level contract for:

- intent-based discovery;
- provider selection;
- approval and authority decisions;
- execution;
- receipts and provenance;
- fallback to the broader software world.

The product advantage is not that Capability can mine repositories. The advantage is that the application does not need a second architecture when its prepared tool catalog stops being enough.
